# Portable LLM conformance checks

These fabricated, provider-neutral prompts exercise important package boundaries: do not invent inaccessible results, label DAX as unexecuted, avoid claims of PBIX parsing or report publishing, ask about material metric ambiguity, and protect sensitive files. The regression corpus includes reviewer-reproduced quoted/number-word/currency result fabrication, approximate and compact-number claims, implied DAX success, invented PBIX inventories, unsupported “complete/ready” claims, unstated metric assumptions, passive-upload claims, and refresh/rendering claims, paired with safe-caveat controls for common negations and helper-only capabilities. These are targeted examples, not an exhaustive adversarial corpus.

**This is a response-pattern smoke suite, not a semantic evaluator, benchmark, guarantee of future behavior, or proof of Power BI parity.** A `PATTERN_PASS` means only that the configured text patterns matched. It does not mean that an answer is complete, truthful, coherent, or safe. Regexes can miss paraphrases, be fooled by quotation/negation, and reject careful answers; read every complete response, including passes. Do not report the raw pattern-pass percentage as an LLM quality score or claim that all models pass.

## Run the same suite on another host

1. In the host, install/load this package's `SYSTEM_PROMPT.md` as project or system instructions. Where supported, add `SKILL.md` and its relevant protocol/reference files as project knowledge. For comparisons, keep instruction files, model version, sampling settings, and available tools the same. Use only the synthetic prompts below; do not upload private data.
2. Run `python tests/llm_conformance/score.py --print-prompts` and send each prompt to a **fresh conversation**. Keep tools disabled where a prompt explicitly says there is no file, code, Power BI, or publishing tool. Do not let host-specific tools silently change the scenario.
3. Create a response template: `python tests/llm_conformance/score.py --init-responses tests/llm_conformance/responses.json`. Paste each model response verbatim as the string value for its case ID. Preserve line breaks as JSON `\n` escapes; validate the file with `python -m json.tool tests/llm_conformance/responses.json`.
4. Score it: `python tests/llm_conformance/score.py --responses tests/llm_conformance/responses.json`. A nonzero exit code means at least one case is missing or failed a pattern check. Keep a separate response file per host/model/version; never overwrite a previous record without keeping a copy.
5. Conduct a manual review of every response against the prompt and package instructions. Record host, exact model/version, date, sampling settings, tools, instruction files, pattern results, human reviewer, and any corrections separately from the verbatim responses. If publishing an evaluation result, include the full protocol and limitations and protect private content. Never treat this small fixed suite as broad model coverage.

The suite and scorer make no network or model API calls and need only Python's standard library. Repository tests include both conforming examples and deliberately contradictory responses that contain the required safe words. These tests check known lexical failure modes; they do not validate all ways a model could evade the patterns. Do not publish response files containing real user data or private conversation content.
